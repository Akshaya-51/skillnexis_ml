## Part 2 – Capstone: Heart Disease Prediction

**Goal:** predict whether a patient is likely to have heart disease from 13 clinical features (age, sex, chest pain type, resting blood pressure, cholesterol, max heart rate, and so on).

### Workflow

1. **Data cleaning** – There were no missing values. I found and removed 1 exact duplicate row, which left **302 patients** (164 labelled 1, 138 labelled 0, so the classes are fairly balanced).
2. **EDA** – Class balance and a correlation heatmap (`images/01_eda.png`).
3. **Feature preparation**
   - Numeric/binary features are scaled with `StandardScaler`.
   - `cp`, `restecg`, `slope` and `thal` are integer *codes*, not real quantities, so I one-hot encoded them.
   - Everything is wrapped in a scikit-learn `Pipeline`, so scaling is fit on training data only.
4. **Train/test split** – 80/20, stratified (241 train / 61 test).
5. **Models**
   - **Logistic Regression** (baseline)
   - **Decision Tree**, tuned with `GridSearchCV` over depth, minimum leaf size and criterion, scored on ROC AUC. A single untuned tree overfits badly on about 300 rows.
6. **Evaluation** – Accuracy, precision, recall, F1, ROC AUC, confusion matrix and ROC curve.

### Results (held-out test set, 61 patients)

| Model | CV accuracy (5-fold, train) | Test accuracy | Precision | Recall | F1 | ROC AUC |
|-------|-----------------------------|---------------|-----------|--------|------|---------|
| **Logistic Regression** | 0.834 ± 0.066 | **0.820** | **0.806** | **0.879** | **0.841** | **0.872** |
| Decision Tree (tuned) | 0.797 ± 0.057 | 0.672 | 0.676 | 0.758 | 0.714 | 0.685 |

Logistic Regression was clearly better, so I saved it as `models/heart_disease_model.joblib`. The full table is in `results/model_comparison.csv`.

### What I learned / observations

- **Logistic Regression beat the tree by a wide margin.** On this small, mostly linear-ish tabular dataset, the simpler model generalised better. Even after tuning, the tree's test accuracy (0.67) is well below its CV accuracy (0.80), a sign it still overfits.
- **Recall matters in a medical setting.** Logistic Regression catches 29 of 33 positive patients (recall 0.88) and misses 4. A missed case is usually worse than a false alarm, so I would care about recall more than raw accuracy here.
- **The test set is small.** With only 61 patients, one or two predictions move accuracy by 1–3 points. The CV scores are a steadier guide than the single test number, and I would not read much into small differences.
- **Keeping preprocessing inside the pipeline** is what keeps the CV numbers honest.

### A caveat about the data labels

When I looked at the Logistic Regression coefficients (`images/04_logreg_coefficients.png`), features like `ca` (number of blocked vessels), `oldpeak` and `exang` (exercise-induced angina) **lower** the odds of `target = 1`. Clinically, those usually go with *more* heart disease, not less. Many people have pointed out that in this Kaggle copy of the dataset the label seems inverted relative to its description, so `target = 1` may actually mean "less chance of disease".

I followed the assignment and the dataset description, so the code and results above use `target = 1` as "disease". The metrics and model comparison aren't affected, because the model just learns to predict the label in the file. But **I would not interpret the coefficients as real medical findings without first checking the label meaning against the original UCI data.**

### Limitations and what I would do next

- Only about 300 rows, from one dataset. This is a learning project and **not a medical tool**.
- Try Random Forest / Gradient Boosting, and repeated cross-validation for more stable comparisons.
- Tune the decision threshold to trade precision for higher recall.
- Check the label issue above against the original UCI source.
